## 3. 本次变更记录（2026-08-25：新增 `.txt` 文件支持）

### 3.1 背景

- 方案文档第 17 节承诺"仅创建 `.md` 和 `.txt`"，但 `files.py` 实际只放行 `.md`，用户要求 `.txt` 时会回复"只支持创建 .md Markdown 文件"。
- 研究模块 `research.py` 的意图正则已识别 `txt`，卡点仅在文件工具，改动范围小。

### 3.2 变更内容

| 文件 | 变更 |
| --- | --- |
| `backend/app/tools/files.py` | 新增 `_SUPPORTED_EXTENSIONS = {md, txt}`；意图正则 `_FILE_NOUN`、`_NAMED_TEXT_FILE` 支持 `.txt`；`validate_markdown_filename` 放行 `.md`/`.txt`（用 `Path.suffix` 判断）；同名排重改用 `Path.stem/.suffix`；`.txt` 返回 `text/plain` mime |
| `backend/app/agents/action_guard.py` | 能力边界文案改为".md 或 .txt"；`_FILE_REQUEST` 正则加入 `txt` |
| `backend/app/api/chat.py` | 成功消息按扩展名显示（.txt → "已创建 文本文件"）；失败消息通用化为"文档文件没有创建成功" |
| `backend/tests/test_file_tool.py` | 拒绝用例 `.txt`→`.pdf`；新增 3 个 `.txt` 用例（创建+mime、同名排重、意图提取） |
| `backend/tests/test_action_guard.py` | 同步能力文案断言 |
| `frontend/src/stores/chat.ts` | `ChatArtifact.mime_type` 扩展为 `'text/markdown' \| 'text/plain'` |
| `frontend/src/stores/chat.test.ts` | 同步失败文案断言 |

### 3.3 行为变化

- 用户请求"创建 txt 文件放桌面"→ 走完整研究链路后创建真实 `.txt`（UTF-8、校验、不覆盖）
- 前端产物卡片显示 `.txt` 文件名、绝对路径、大小、SHA-256，mime 为 `text/plain`
- 仍拒绝 `.pdf`/`.docx` 等扩展名与任意路径

### 3.4 验证

- 后端全量 208 passed；前端 39 passed；生产构建通过
- 端到端：在真实桌面创建 `.txt`（`text/plain`、SHA-256 校验成功），验证后删除

### 4.5 P3：记忆、主动陪伴、语音与安全深化（对齐《数字人陪伴 Agent 后续开发方案》）

- 记忆确认/编辑/删除/冲突/过期/检索排序

- 数字人表达：VRM 模型替换、表情状态机、口型同步、动作编排
- 安全：隐私面板、数据导出删除、敏感内容分级与评测

### 4.6 P3：光原式陪伴桌面（新策划方向，2026-08-12）

- 定位：粒子球视觉生命体替代"拟人脸"路线，避开恐怖谷；球随记忆数据生长是差异化卖点。
- P0：陪伴模式（粒子球 + 字幕浮层 + 语音律动 + 情绪着色），建议先做静帧原型调观感
- P1：仪表盘 + 统计 API + 应用坞（包装现有功能入口）
- P2：桌面外壳（推荐 Tauri）+ 性能分级 + 开机自启
- P3：硬件联动预研
- 原则：不破坏现有聊天模式，两种模式并存；WS 协议与对话链路零改动
