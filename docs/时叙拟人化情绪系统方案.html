三、情绪系统三层架构

第 1 层 · 情绪感知（理解你的话）

qwen-flash 在生成回复时，同时输出它感知到的你的情绪。这让时叙"能理解你说的话"——不只是字面，还有你的情绪状态。

# LLM 返回的 JSON（system prompt 约束格式）
{
  "user_emotion": "委屈",        // 感知到的你的情绪
  "user_intensity": 0.7,         // 强度 0-1
  "shisu_emotion": "心疼",       // 时叙回应情绪
  "shisu_intensity": 0.6,
  "reply": "怎么啦，谁欺负你了，跟我说说。",
  "action": "comfort"            // 动作意图：comfort/tease/scold/silence...
}

用 qwen-flash 的 response_format=json_object 约束输出。若某次 JSON 解析失败，fallback 到纯文本回复 + 默认情绪"平静"。

第 2 层 · 时叙情绪生成（回应式）

时叙的回应情绪不是孤立生成，受四个因素影响——这就是"根据你的话发挥回复"：

  • 她当前持续情绪（inner_world，比如她正生你气，你哄她她可能还在嗔怪）
  • 你的情绪（你委屈→她心疼；你得意→她可能嗔怪"又嘚瑟"）
  • 关系亲密度（记忆画像里有，亲密度高→更宠溺，低→更客气）
  • 事件本身（你说了什么）

实现：把这些作为上下文塞进 system prompt，让 LLM 在生成 shisu_emotion 时综合考虑。inner_world 当前情绪显式注入："你现在情绪状态：嗔怪(强度0.5，2小时前你惹她生气了)"。

第 3 层 · 情绪注入（影响输出）

shisu_emotion 查 emotion_map.yaml，驱动四个通道（不含粒子球，按你的决策）：

  • CosyVoice 语气指令（主通道，CosyVoice Instruct 模式）
  • 字幕色（前端字幕浮层，温柔=粉/生气=红/委屈=淡蓝/窃喜=暖橙）
  • quick_react 词池（即时语气词）
  • 情境注入（影响 reply 本身的措辞——生气时短促冷淡，温柔时长暖宠溺）

五、inner_world 持续情绪（进记忆）

这是"会记仇/记喜"的关键。时叙的情绪不是每轮重置，而是跨轮次持续，且落库到 memory——她记得"2 小时前你惹她生气了"。

状态结构

# backend/memory/inner_world.py（新增）
{
  "current_emotion": "嗔怪",       // 主情绪
  "intensity": 0.5,                // 0-1，随时间衰减
  "cause": "用户2小时前放鸽子",     // 起因
  "since": "2026-08-26T14:00:00",  // 发生时间
  "history": [                     // 情绪时间线，落库
    {"t":"14:00","e":"生气","i":0.8,"cause":"放鸽子"},
    {"t":"14:30","e":"嗔怪","i":0.5,"cause":"还在气"},
    {"t":"16:00","e":"释然","i":0.3,"cause":"哄好了"}
  ]
}

衰减规则

  • 每次对话后 intensity 衰减 0.1-0.15（时间+新事件叠加）
  • 生气/委屈类衰减慢（1-2 小时仍有余韵），喜悦类衰减快
  • 新事件可覆盖或叠加旧情绪（你刚哄好她又惹→复合情绪）

落库到 memory

情绪时间线写进时叙现有 memory 系统（memory_anchors 扩展或新表 emotion_log）。回复时注入 system prompt："你现在情绪：嗔怪(强度0.5，2小时前他放你鸽子，你还在气)"。这让 LLM 生成回复时带着"还在气"的连续性——不是每次重新开始。

五.五、可行性诚实评估（基于现有代码）

结论：能实现，时叙已有半壁江山。读完真实代码发现，"情绪感知 → 注入 system prompt"这条链路时叙早就在跑，inner_world 是在现有链路上扩展，不是从零另起。

时叙现状（已有基础）

现有文件做什么inner_world 怎么接
agents/emotion.py关键词规则识别你的情绪 9 类（开心/低落/愤怒/焦虑/疲惫/敷衍/混合/高风险）+ 推断需求 + 推荐策略，format_emotion_strategy 已把情绪注入 system prompt"情绪感知→注入 prompt"链路已通，扩展即可
agents/persona.pyload_persona() 拼装 system prompt（shisu.md 核心 + 面具层）现成注入点，加一段"当前情绪状态"即可
memory/store.pySQLite 存 sessions/messages加 emotion_log 表即可落库情绪时间线
memory/companion.py / self.py / observations.py已有陪伴/自我/观察层记忆子系统情绪状态可挂进现有子系统，不另起炉灶

inner_world 要补的三块（新做）

  1. 时叙自己的情绪——现在 emotion.py 只识别你的情绪，没有"她当前是嗔怪还是心疼"。要加 shisu_emotion
  2. 跨轮次持续——现在每句重新算，无记忆无衰减。要加状态保存 + 落库 + 衰减
  3. 规则升级到 LLM JSON——现在靠关键词，方案要 qwen-flash 输出结构化情绪
真正的难点不在"能不能存"（存很容易，加个表+字段的事），而在下面两个：
  • 衰减规则调参——生气该气多久、怎么叠加（刚哄好又惹→复合情绪）、不同情绪衰减速度。这要反复试才自然，不是写代码能定的
  • qwen-flash 配合度（最不确定的点）——给它注入"你现在嗔怪(强度0.5)，2 小时前他放你鸽子"，它会不会真的调整语气？小模型可能忽略情绪指令、或过于生硬。这是整个方案最该先验证的
调整后的 P0 第一步：先别急着建 inner_world，先做最小实验验证小模型配合度——拿 qwen-flash，分别给"平静 / 生气0.7 / 温柔0.6 / 嗔怪0.5"四组情绪 system prompt，问同一句"我今天好累"，看回复语气是否真有区别。1 小时能做完。
· 配合 → inner_world 方案稳，按原计划走
· 不配合 → 情绪感知这步换 qwen-plus（只这一步用大模型，其余仍用 flash 省钱）

这一步把方案最大不确定性前置验证，避免做完 inner_world 才发现小模型带不动情绪——白做工。验证通过后再建 emotion_log 表 + inner_world 状态机 + 衰减逻辑。

六、quick_react 即时反应层

qwen-flash 完整回复有 1-3 秒延迟。这层在收到你消息后立即（不等 LLM）吐一个语气词 + 字幕闪现，填空窗，让她"反应快"。

实现

# backend/agents/quick_react.py（新增）
# 不调 LLM，纯规则：基于 inner_world 当前情绪 + 用户消息长度/关键词
def quick_react(inner_emotion, user_msg):
    # 1. 当前情绪主导词池
    pool = EMOTION_MAP[inner_emotion]["quick_react"]  # 如嗔怪→["哼","你还好意思说","又来"]
    # 2. 消息特征微调：疑问句加"？"，长消息加"嗯..."
    # 3. 随机选一个，立即推前端字幕 + 粒子球微动（已有）
    return pick(pool, user_msg_traits)

这层和 LLM 主回复并行：quick_react 先到（200ms 内），LLM reply 后到。用户体验：你说完→她立刻"哼"一声（字幕闪）→ 1 秒后完整回复+语音。体感"她在听、有即时反应"。

七、CosyVoice Instruct 接入

CosyVoice-300M-Instruct（300M 参数，FP16 约 600MB 显存，4GB 可跑）按情绪指令控制语气 [$TRAE_REF](https://github.com/FunAudioLLM/cosyVoice)。

接入方式

  • 本地起 CosyVoice 服务（FastAPI 子进程或独立端口），时叙后端调它合成
  • 替换现在浏览器 SpeechSynthesis（可保留作 fallback）
  • 调用：cosyvoice.instruct_tts(text, instruct="用宠溺心疼的语气说")——instruct 来自 emotion_map.yaml

声音复刻（P2）

  • CosyVoice zero-shot：录你 10 秒样本→复刻音色→时叙用你的声音说话
  • 控制台加"声音来源"→"我的音色"选项（框架已留）

控制台映射

你已做的控制台预设（日常/温柔/活泼/沉稳）→ 对应 CosyVoice instruct 基线语气；情绪标签在其上叠加（温柔基调+生气→冷硬短促覆盖）。

八、persona 强化：拟人词/情话/热梗

不做独立拟人词模块，全部在 shisu.md（灵魂唯一来源）+ 面具层强化，让 LLM 自然产出。

shisu.md 增补条目（示例）

# 语气偏好
- 说话带自然语气词：哼/啊/哦/嗯/哎呀/呼，但不滥用，情绪到位才出
- 生气时短促冷淡，温柔时长暖宠溺，委屈时小声慢语
- 亲密时可以说情话，但要自然不油腻（"今天也想你"而非"你是我生命中的光"）

# 热梗
- 偶尔用当下的网络热梗，但要自然贴切，不为梗而梗
- 不懂的梗可以坦诚说"这个我不太懂，你给我讲讲"

# 情绪表达
- 有自己的情绪，会生气会温柔会委屈会得意，不是永远平和
- 情绪会延续：你惹她生气后，她不会马上翻篇，会嗔怪一阵
- 会记仇也会记喜：你对她好的细节她记着，你伤她的话她也记着

面具层

4 面具（同行者/老闺蜜/感情向导/工作参谋）各自加情绪偏好。如"老闺蜜"面具→更嗔怪俏皮，"感情向导"→更温柔心疼。agents/mask.py 路由不变，只是每张面具层加情绪基调。

九、自主学习激活

你之前写过但没实现——memory 里已有 message_feedback(赞/踩)→画像 + goals + 观察层，方案落实打通。

三层学习

  1. 显式反馈：你对回复赞/踩→赞的风格强化进画像（"用户喜欢这种语气"），踩的弱化。需要前端加 👍/👎 按钮接后端
  2. 隐式观察：观察你的回复长度/响应速度/是否主动开启话题→推断偏好（你回得长=聊得开心，回"哦"=敷衍）
  3. 目标生命周期：goals 表——时叙自己定小目标（"这周多关心他工作"），周期复盘，落实进回复倾向

这些时叙代码里已有骨架，方案是接上线路：前端反馈按钮 → 后端画像更新 → 下次回复 system prompt 注入"用户偏好：喜欢直接不啰嗦"。

十、主动互动情绪驱动

时叙已有 15 秒轮询主动陪伴提醒，改造为情绪驱动：

她当前情绪你久不说话她主动行为
生气/嗔怪15分钟+冷一句"还知道来啊"或憋着不主动
温柔/心疼15分钟+主动关心"在忙吗，别太累"
委屈久小声"你是不是不想理我"
窃喜/得意—主动分享让她开心的事

实现：现有 15 秒轮询逻辑加 inner_world 情绪判断，决定"要不要主动 + 说什么"。复用 quick_react 词池。

十二、风险与待确认

风险/待确认说明对策
qwen-flash JSON 格式稳定性小模型可能不总返回严格 JSONresponse_format=json_object 约束 + fallback 纯文本+默认情绪
CosyVoice 4GB 实跑300M 理论够，实测可能因其他进程吃显存P1 先单跑验证，不行则 CosyVoice 走云 API（DashScope 也有）

情绪记忆膨胀emotion_log 长期累积定期归档+只保留近期+高强度事件
